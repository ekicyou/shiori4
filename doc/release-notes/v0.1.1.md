## 今回の見どころ

### SHIORI/2.x の要求と応答を扱う便利関数 (#16)

`shiori4_host::shiori2` に、SHIORI/2.x で話す従来の DLL のための要求の組み立て（汎用の `request` と、命令ごとの 9 つの関数）、応答の読み分け（`Response::parse` と、決まったヘッダの取り出し）、先頭の 8 バイトだけで SHIORI/2.x と SHIORI/3.x を見分ける `version_of` を置いた。どの OS・arch でも使え、文字コードには触れない。

### x86 の Windows で従来の SHIORI/3.0 の DLL を読める (#15)

x86 の Windows だけで、`LegacyRuntime` により、従来の SHIORI/3.0 の DLL（`load`・`loadu`・`request`・`unload`）を `shiori4_host` から動かせるようにした。要求はバイト列のまま往復する。試験用のホストにも `--entry legacy` を足した。

### 動きが変わる点

- x86 の Windows では、`load_ghost`・`load_ghost_with` に相対のライブラリのパスを渡すと、開かずに `LoadError::InvalidPath` を返す。ほかの環境は変わらない。 (#15)
