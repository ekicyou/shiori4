## 今回の見どころ

初めての版。SHIORI とホスト（ベースウェア）をつなぐ新しい ABI と、その上で SHIORI・ホストを作るための 2 つのクレートを出した。

### SHIORI とホストの間の C ABI を定めた

`shiori4_abi` は、SHIORI とホストの間でバイト列をどう運ぶかだけを定めた C ABI である。SHIORI が公開するシンボルは `shiori_get_api` の 1 つだけで、ホストは版を渡して関数テーブルを受け取る。

- 版は 2 つ。既定の v4 はヘッダ部分だけを運び、SHIORI からホストへの同期の問い合わせ（`host.request`）と、任意のスレッドからの `post` を使える。v3 は SHIORI/3.0 の全文を運ぶ互換の版である。
- 所有権・戻り値・スレッドの規約を持ち、パニックは `SHIORI_E_PANIC` に変えて境界を越えさせない。
- C ヘッダ `include/shiori4_abi.h` が付き、Rust 以外の言語からも使える。

### SHIORI を Rust で作れる

`shiori4` は SHIORI 側の高水準層である。`Ghost` trait を実装し、`export_ghost!` でエクスポートすれば SHIORI になる（`crate-type = ["cdylib"]`）。

- v3 と v4 の文字列の形の差を吸収する。
- ヘッダの解析と生成（`Headers`・`HeaderWriter`）、プロパティの取得（`Properties`）、`post` の受付 ID の待ち合わせ（`PendingTags`）を持つ。
- ホストとの間のメッセージ名（`host_protocol`）を、ホスト側のクレートと共有する。

### SHIORI を読み込んで動かすホストを Rust で作れる

`shiori4_host` はホスト側の高水準層である。`Host` trait を実装し、`GhostRuntime::load` で SHIORI（v4）を読み込む。

- SHIORI のライブラリ（DLL・.so・.dylib）の読み込みとライフタイムをまとめて管理する。
- SHIORI からの同期の問い合わせを `Host` に振り分ける。
- 任意のスレッドから来る `post` をキューに積み、`Host::wake` を受けてイベントループから `GhostRuntime::pump` を呼ぶと、完了やイベントを規約どおりの時点で SHIORI に届ける。

### 3 つのクレートを crates.io と docs.rs で読める (#3)

`shiori4_abi`・`shiori4`・`shiori4_host` を crates.io に公開した。版はワークスペースで 1 つにそろえ、各クレートに日本語の README と MIT ライセンスの本文を同梱した。使用例と規約の詳細は docs.rs のクレートのドキュメントにある。
